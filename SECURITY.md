# Security Policy

## Reporting a vulnerability

Please **do not** open a public issue for security problems.

Report privately via either:

1. GitHub's [private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability) on the affected repository (**Security** tab → **Report a vulnerability**), or
2. Email the organization owners listed on the [organization profile](https://github.com/Synaptivora).

Please include:

- The affected repository and version or commit
- A minimal reproduction, if available
- The impact you believe the issue has

## What to expect

| Stage | Target |
|---|---|
| Acknowledgement | within 3 working days |
| Initial assessment | within 7 working days |
| Fix or mitigation plan | communicated with the assessment |

Please allow reasonable time for a fix before any public disclosure. Credit will be given in the advisory unless you prefer otherwise.

## Scope

This policy covers source code and build/release configuration in Synaptivora repositories. It does not cover third-party dependencies — report those upstream, though a heads-up is appreciated.
